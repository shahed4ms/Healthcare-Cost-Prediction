# A Budget Forecast That Learned to Say “Not Yet”

Imagine a healthcare planning team preparing next year’s budget. Before anyone orders a complicated forecasting platform, the team asks a smaller question: can a few basic patient characteristics provide a useful first estimate of annual costs? I explored that question with the supplied healthcare-cost dataset, using age, BMI, smoking status, and chronic-condition status as candidate inputs.

I started by checking what the file actually contained. It had 50 records, a numeric `AnnualCost` target, no exact duplicate rows, and no missing values. `PatientID` was unique, but I left it out of the model: an identifier can help locate a record, but it does not explain healthcare needs. I also compared annual-cost summaries by smoking status. In this sample, the smoker group’s mean was about 10,420 cost units and the non-smoker group’s was about 9,614. That is a description of these records, not evidence that smoking caused the difference.

Next, I built a small regression pipeline. A reproducible 80/20 split reserved 10 records for testing. The pipeline median-imputed numeric fields and imputed then one-hot encoded categorical fields, keeping preprocessing inside the training workflow. I chose linear regression because it is a straightforward starting point for predicting a numeric value. More importantly, I compared it with a mean-only benchmark: a model that ignores patient characteristics and always predicts the average cost in the training set.

The result was a useful surprise. On this split, linear regression’s mean absolute error (MAE) was about 1,997, while the mean-only benchmark’s MAE was about 1,671. Regression’s R² was approximately -0.41, also worse than the benchmark’s -0.07. The features did not improve the estimate here. With only 50 records and 10 test cases, these numbers are unstable—but hiding the weak result would defeat the purpose of evaluation.

In a real planning project, a validated model might help teams compare broad budget scenarios and identify where better data is needed. It should not determine an individual’s care, coverage, or price. A responsible next step would be to gather a larger, representative dataset, clarify how costs are recorded, test performance across multiple splits, and involve clinical, privacy, and fairness reviewers. For now, this mini-pipeline’s most valuable forecast is a reminder: sometimes the honest answer is “not yet.”
